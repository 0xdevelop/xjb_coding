## 实现选择

- 顶层入口为 `skills/bruno-api-tests/SKILL.md`；沿现有插件的 `skills/` 分发与宿主发现方式，用户无需额外安装三个官方 skills 或手工同步后端。
- `extend/local.md` 明确完整场景、参数与文件接续、真实执行和失败处理；官方资料按任务从 `references/official-docs.md` 读取。
- 关联官方生成、测试、CI skills 及官方文档索引。上游的占位符、TODO、Python helper 或 Docker 默认不能覆盖本仓约定。
- 沿 `update_upstreams.sh` 现有在线引用检查与 `git_tag.sh` 维护链，不新增生成器、更新器、定时器或状态账本。在线检查验证可达性，生成时读取最新正文并核目标版本；不宣称离线正文快照已同步。
- 修复已有集合时复用当前格式、请求、用户修改和授权的运行上下文；识别过期 ID、运行变量及未打包附件，不通过重建业务对象掩盖依赖缺口。

## 失败路径与处置

| 场景 | 处置 |
| --- | --- |
| 缺少真实凭证、业务输入或人工验证码 | 先从授权上下文核查；仍缺时仅询问不可推导的必要项，不编造、不标即用 |
| HTTP 200 但异步任务运行中或业务失败 | 按业务响应判断完成与失败；轮询有界，超时或失败停止后续依赖 |
| 空运行状态、重开集合或再次执行 | 检查变量作用域、失效清理与续做入口，避免旧值串用和重复写入 |
| 附件或脚本依赖当前机器环境 | 打包必要材料、采用集合相对路径与原生能力；依赖缺失在交付前修复 |
| 官方网页不可达、版本不符或宿主能力不足 | 报告实际缺口；不能以链接检查、模拟响应或仅 CLI 结果冒充真实 GUI 验收 |
