# 规划原型

产出**一份**自包含 HTML 原型，看完就能落码，不用再翻别的文档。

## 用法

```
/planning-prototype <需求名>
/planning-prototype <需求名> --stages-only     # 先只列阶段划分与发起方，确认后再画界面
/planning-prototype <需求名> --out <文件路径>   # 指定输出路径
```

产出物命名：`<功能域>_规划原型_<日期>.html`，落在目标项目的文档目录。

## 开工前的交互问询

原型的价值全在字段准不准。缺料就动手，画出来的是想象，不是需求。

**顺序：先自己查，查不到才问，一次问齐。** 能从仓里、文档里、方法表里拿到的，不许拿去问人——问了就是把自己的活推给对方。

### 七项必备

| # | 必备项 | 先去哪查 | 查不到才问 |
| --- | --- | --- | --- |
| 1 | 功能域名称与一句话目标 | 用户这句话本身 | 「这轮原型覆盖到哪一步为止？」 |
| 2 | 涉及哪几端、各自角色 | 项目架构文档、已有原型 | 「除了用户端和运营端，还有别的端参与吗？」 |
| 3 | 阶段划分与每段发起方 | 已拍板的方案文档 | 先提一版划分请对方确认，**不要让对方从零列** |
| 4 | 服务端方法表或其快照位置 | 仓内搜方法注册表 / 快照文件 | 「方法快照在哪个路径？」 |
| 5 | 工作流定义体位置与编号 | 仓内 `workstream_*.json` | 「这条链用到哪几个定义体？」 |
| 6 | 外部供应商对接文档 | 项目文档目录下的对接文档原件 | 「对接文档原件在哪？」 |
| 7 | 输出路径与文件名 | 项目惯例 | 默认 `<功能域>_规划原型_<日期>.html`，无异议就不问 |

### 问的方式

- **一次问齐**。把缺的几项合成一条消息问完，不要一项一答挤牙膏。
- **带默认值问**。每项给出你的推荐，对方回「按默认」就能过，而不是逼人从零写。
- **先提再确认**。阶段划分这类，先提一版自己的划分请对方改，比让对方列清单快得多。
- **问完即停**。拿到答复前不要先画——画错了返工比多问一句贵。

### 可以不问就开工的情况

七项都能从仓里查齐，且阶段划分有拍板记录可依。这时直接出原型，在原型顶部标明每项的出处，让对方核对出处而不是核对结论。

## 五条硬规矩

1. **只出一份文件**。多份看着全面，实际是同一批界面在三处漂，维护心智负担更重。用「阶段切换 + 视角切换」在一份里承载全部。
2. **这个阶段不落码**。只出原型；原型定稿前不碰业务代码。
3. **字段不许编**。每个字段名、必填性、接口路径都要有出处。写不出出处，就不要写进原型。
4. **类型声明是断言不是校验**。返回值形状不能只看 Go / TypeScript 的类型声明，要么打真接口看回包，要么读服务端真正拼返回值的那几行代码。
5. **判据唯一**。界面开不开闸只看服务端给的可执行动作列表与可选性字段，原型里不画「前端自己算」的分支。

## 两端职责的默认分界

沿用，不要每次重新定；要改先找拍板记录。

| 类别 | 归谁 | 依据 |
| --- | --- | --- |
| 专业决定（定数量、填规格、受理例外、放行方案） | 用户端 | 代客不得代到专业判断上 |
| 与外部供应商交涉（录返回表、录结果） | 运营端 | 恒由平台发起 |
| 执行段（下单一类，不含专业决定） | 用户端；代客路径运营端可代起 | — |
| 供应商标识与原文（项目号、轮次号、单号、错误码、原始回包） | **只在运营端** | 用户端一处不出现 |

**边界要具体到字段。** 同一条偏差：用户端显示「纯度 86%（阈值 90%）· 可用」，运营端显示「purity 0.86 · `QC_PURITY_BELOW_THRESHOLD` · 来源 CRO」。只写「运营端能看到供应商信息」等于没写。

## 动手前必答的七个问题

每一段都先答完再画，答不上就是还没摸清。

| 序号 | 问题 |
| --- | --- |
| 1 | 这一段由哪一端发起？发起动作的标识是什么？ |
| 2 | 具名确认点是哪个？确认人姓名之类的字段是不是外部合同要求的？ |
| 3 | 落到哪个工作流定义体的哪几个任务？ |
| 4 | 打外部供应商哪个接口？必填哪几个参数？ |
| 5 | 返回值里哪些要回报给业务事实源？回报方法与必填是什么？ |
| 6 | 失败怎么走——重试、退回、还是结项？**分清「终局但不是失败」**（如漏斗走到底该结项，不是报错重试）。 |
| 7 | 哪些字段属于外部供应商事实，必须挡在用户端之外？ |

## 一份原型的形状

单个 HTML，自带样式与脚本，无外部依赖，不引 CDN。

**阶段切换**：顶部横向一排按钮，一段一个，按钮上标出该段由哪一端发起。

**界面要画实，靠缩放不靠省略。** 每一屏按固定设计宽度（如 460px）写足细节——真实字段名、真实数值、真实状态、真实校验结果。对照区只用 `transform: scale(列宽 / 设计宽度)` 等比缩小，点「放大」在浮层里以 `scale(1)` 看原尺寸。

**两处必须是同一份 DOM**：写一个 `frame(端, 阶段)` 函数产出界面，对照区与放大层都调它。绝不为缩略图另写一版简化的——那是两套内容，改一处漏一处。缩略图里看不清的东西，放大后必须逐字一致地在。

判断标准：把缩略图放大后，能不能直接照着填代码？「已冻结 40 条」这种是实；「显示候选数量」这种是虚，重写。

**视角切换**：三个页签。

| 页签 | 内容 |
| --- | --- |
| 两端界面 | 左右两屏并排对照。各自写清页面路径、真实控件（可选 / 置灰 / 必填标记）、等待态、边界提示。**置灰控件必须写明原因**，不是让它消失。 |
| 调用链与传参 | 五列表格：步骤 / 发起方 / 调用 / 入参 / 说明与返回值。一行一跳，从界面动作到服务端方法、到工作流任务、到外部接口、到回报方法，一条不省。下面再跟一张关键字段表：字段 / 来源 / 必填 / 去向与约束。 |
| 各端要补的 | 两栏，分别列每一端要补的界面能力与健壮性。写具体动作，不写「要健壮」这种空话。 |

## 怎么取到真字段

| 来源 | 取法 |
| --- | --- |
| 服务端方法的入参与必填 | 从方法注册表或其落盘快照取；快照过期先重新生成再取，不要凭印象补。 |
| 工作流定义体的任务与外部接口 | 解析定义体 JSON。**任务不在顶层**，在 `steps.*.stages[].tasks`。 |
| 外部供应商的必填与返回值 | 只认对接文档原件，不认转述，不认二手摘要。 |

```bash
# 工作流定义体：任务标识 / 别名 / 请求方法 / 请求地址
python3 -c "
import json
d=json.load(open('<定义体 JSON 路径>'))
for st in d['steps'].values():
    for stage in st.get('stages', []):
        for t in stage['tasks']:
            print(t['task_id'], t.get('alias'), t.get('request_method',''), t.get('request_url',''))
"

# 方法快照：某个方法的必填与全部可选键
python3 -c "
import json
m=json.load(open('<方法快照路径>'))['methods']
print(json.dumps(m['<方法名>'], ensure_ascii=False, indent=2))
"
```

**架构与职责归属类问题不许从代码推断。** 谁拥有这个能力、这一段该归哪一端，去找拍板记录的原话；找不到就问人。现状可能只是迁移到一半的形状。

## 常见跑偏

| 跑偏 | 为什么是坑 |
| --- | --- |
| 把跨接口的组合逻辑放进网关层 | 网关长出业务逻辑，就成了第二个定义能力的地方。同一条规则两处维护，迟早对不上。 |
| 代客代到专业判断上 | 发起动作与具名确认必须同归一方。分开之后确认只剩追认，签的名对不上做的事。 |
| 拿「代码现状」当「应该如此」 | 尤其注释里写着「本轮不改」的地方，那是债不是规范；照抄等于把债浇成水泥。 |
| 只画顺利路径 | 落码时每人各编一套走法，上线才发现同一个失败有三种结局。 |
| 两端各算各的判据 | 同一件事算出不同结果，用户看到能点、运营看到不能点，谁都说不清哪个对。 |
| 把「终局」画成「失败」 | 该结项的路径给了「重试」，用户反复点一个必然失败的按钮。 |

## 交付前自查清单

- [ ] 只产出一份 HTML 文件，无外部依赖
- [ ] 界面按固定设计宽度画实，对照区等比缩放，可点开看 1:1；缩略图与放大层是同一份 DOM
- [ ] 每屏的数值、状态、校验结果都是具体值，没有「显示 XX」这类占位描述
- [ ] 每一段的七个问题都答全，答案落在原型里，不是留在聊天记录里
- [ ] 每个字段都有出处（方法快照 / 定义体 / 供应商文档），无一处凭印象
- [ ] 每一段至少写清一条失败去向，且分清重试 / 退回 / 结项
- [ ] 每个置灰控件都写了置灰原因
- [ ] 边界提示具体到字段名，不是「注意权限」这类空话
- [ ] 取字段用的命令**真跑过一次**，不是照抄模板
- [ ] 七项必备在开工前已补齐，靠查得到的没去问人
- [ ] 没有落任何业务代码
