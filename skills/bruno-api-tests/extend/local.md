# 本仓库约定

本文件约束 Bruno 交付与验收，官方 skills 提供格式和能力参考。用户当次要求、项目架构与授权优先；不因官方示例扩大场景或权限。

## 输入与配置

- 先查真实代码、接口契约、现有集合和获准使用的配置，复用已有能力。地址、鉴权方式、租户关系、业务字段和状态均须有证据；不编造 ID、凭证、业务输入或服务地址。
- 能从已有授权上下文取得的配置由 Agent 接好，不让用户重复填写。秘密沿用目标版本支持的既有秘密引用，不写进 Git、聊天、命令参数、日志或报告；不改用户 `.env`、宿主配置、全局环境或秘密存储。只有变量名而没有实际可解析值，不算接好。
- 不可推导且确实缺失的凭证或业务输入，只问最少必要信息；在补齐前不能标为可直接运行。不要用假值、默认本机地址、示例文件或无效占位符掩盖缺口。
- 官方 skills 中的占位参数、Python helpers、Docker 或自动安装建议不作为本仓执行步骤。按项目现有工具链编辑文件，不复制运行未经核实的上游命令。

## 集合与数据传递

- 保留目标版本支持的原生集合、环境、文件夹、请求和鉴权结构；环境的选中状态也要验。已有集合优先精确修改，不另建同功能集合替代原入口。
- 登录响应的 token、创建响应的 ID、分页游标等按真实响应路径保存，后续读取同一作用域。校验响应成功与字段有效后才更新变量，失败时停止依赖链，不能继续使用上次成功残留的数据。
- `bru.setVar()` 只保存运行时变量，不承诺跨 App 重启或 CLI 进程恢复。需要续做时从真实服务查询或复用已明确保存的运行上下文，不能依赖旧会话的隐藏状态。
- 路径参数使用原生 Path Params，并核对实际发出的 URL；URL、参数和 Body 的变量插值要按真实类型处理，避免未替换的 `{{变量}}`、对象变字符串、数值精度丢失或二次 JSON 编码。不能只检查编辑器显示值。
- 附件随集合交付，使用相对集合根目录的路径和原生 multipart / 文件请求能力；核对字段名、文件存在、类型和实际上传内容。不能依赖 Agent 机器的绝对路径、全局 `fs`、临时文件或外部复制步骤。
- 优先 Safe Mode 下的原生能力。确实需要 Developer Mode 时先说明具体依赖，按用户授权处理；不能通过改全局沙箱、关证书校验或启用任意脚本权限使集合看似可用。

## 流程与失败处理

- 按用户要求区分逐个 Send 与 Collection Runner。`bru.runner.setNextRequest()` 控制 Runner，不能把它写进请求就承诺单次 Send 会自动串完。需要自动调用依赖时核实 `bru.runRequest()` 的路径、返回值与脚本层级，避免集合级脚本递归调用自己。
- 一键流程必须有实际的顺序、条件分支和停止控制；请求编号不能代替执行控制。断言失败也不能代替停止控制，实测失败后不会发出后续依赖请求。可选请求、负例与破坏性请求按场景选择，不能默认混进正常主流程；依赖链不能并行乱序执行。
- 异步任务按真实状态判断完成、失败和取消，设定轮询间隔、次数或总时限；遇到错误终态或超时停止后续写操作并留下失败证据。提交成功或进度到 100 不能代替结果可用。分页校验游标变化与终止条件，防止重复页或死循环。
- 重跑与续做先核对已创建资源和现有 ID，复用接口的幂等或查询能力，避免重复创建、重复付费或重发任务；已有任务排查默认从只读查询继续。不能为跑通流程重建任务或伪造新 ID。
- 清理只作用于本次创建、且授权范围允许处理的资源；失败后的恢复方式须与实际接口一致，不删除用户既有数据。写操作授权不从“生成测试集合”自动推导，必要授权只在具体请求与影响可审查后处理。
- 先核目标版本与协议支持。官方 Collection Runner 当前只执行 HTTP 请求，不包含 gRPC / WebSocket；涉及它们时查对应能力并单独说明执行范围，不能用 HTTP 文件冒充跨协议全流程。

## 验收与证据

- 由 Agent 使用获准的宿主工具在目标 Bruno App 全新导入或打开最终交付物，保留用户已有窗口和集合。没有桌面控制授权时按宿主权限处理，不能擅自操作 App；缺工具或授权则报告 GUI 验收未完成，不能改称“用户导入即可”。
- 从本次交付的完整文件、声明的默认配置与沙箱、无本集合遗留 runtime 变量的起点验证。使用隔离副本或本集合作用域处理状态，不清用户全局变量、cookie 或其他会话；不能依赖事先点过登录、手填过 ID 或预热过的运行状态。
- 在真实后端运行用户要求的 Send 或 Runner 场景，核对实际请求、鉴权、ID 传递、附件内容与业务终态；涉及网关、执行端、数据库或运行时缓存时沿原调用链取证。失败路径、分页和异步超时也要有决定性证据，不以单个 2xx 或绿色断言代替完成。
- CLI 可补充批量回归与报告，版本、环境和沙箱须与目标交付一致；CLI 成功不能证明 GUI 导入、默认环境或跨协议流程通过。使用 mock、固定响应或离线检查时准确标明范围，不当作真实业务联调。
- 报告各场景实际执行结果及尚缺的验证；未完成的项沿现有任务状态保存，不能标为 ready / 已完成。截图、脱敏请求记录和报告放目标项目 `tmp/`，清理本任务额外创建的进程与中间产物。
